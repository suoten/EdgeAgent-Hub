## 第一章 安装部署

### 1.1 Windows 安装（最简单）

> **适合人群**：Windows 用户、快速体验、开发测试
> **所需时间**：约 5 分钟

#### 准备工作

1. 确认你的电脑是 Windows 10 或更高版本（64 位）
2. 确认有至少 512MB 可用内存
3. 确认 8080 端口没被占用（如果占用，后面教你改端口）

#### 安装步骤

**第 1 步：下载发布包**

前往 [Gitee Release](https://gitee.com/suoten/edgeagent-hub/releases) 或 [GitHub Release](https://github.com/suoten/EdgeAgent-Hub/releases) 页面，下载：

```
edgeagent-hub-1.0.0-windows-amd64.zip
```

**第 2 步：解压**

右键点击下载的 zip 文件，选择「解压到当前文件夹」。

解压后你会看到以下文件：

```
edgeagent-hub-1.0.0-windows-amd64-pkg/
  edgeagent-hub.exe      主程序（双击运行）
  config.yaml            配置文件
  install.sh             Linux 安装脚本（Windows 不用管）
  uninstall.sh           Linux 卸载脚本（Windows 不用管）
  README.md              说明文档
```

**第 3 步：运行**

双击 `edgeagent-hub.exe`。

会弹出一个黑色控制台窗口，显示类似这样的日志：

```
INFO  EdgeAgent Hub v1.0.0 starting...
INFO  Storage initialized
INFO  MQTT-NATS bridge initialized
INFO  JetStream streams initialized
WARN  HTTP mode: TLS is not enabled...
INFO  EdgeAgent Hub v1.0.0 started on 0.0.0.0:8080
```

约 2 秒后，浏览器会自动打开 `http://localhost:8080`。

> **如果浏览器没有自动打开**：手动打开浏览器，地址栏输入 `http://localhost:8080`

**第 4 步：停止服务**

直接关闭黑色控制台窗口即可。

#### 修改端口（可选）

如果 8080 端口被占用，用记事本打开 `config.yaml`，找到：

```yaml
server:
    host: 0.0.0.0
    port: 8080         # 改成你想要的端口，比如 9090
```

保存后重新双击 `edgeagent-hub.exe`。

### 1.2 Linux 安装（一键脚本）

> **适合人群**：生产环境部署、工厂服务器、边缘网关
> **所需时间**：约 10 分钟

#### 支持的平台

| 平台 | 架构 | 说明 |
|------|------|------|
| Ubuntu 20.04+ | amd64 | x86 服务器 |
| Ubuntu 20.04+ | arm64 | ARM 服务器 |
| CentOS 7+ | amd64 | x86 服务器 |
| Debian 10+ | amd64/arm64 | 树莓派等 |
| 各发行版 | arm64 | 工业网关 |

#### 安装步骤

**第 1 步：下载发布包**

```bash
# amd64 (x86 服务器)
wget https://github.com/suoten/EdgeAgent-Hub/releases/download/v1.0.0/edgeagent-hub-1.0.0-linux-amd64.zip

# arm64 (ARM 服务器/网关)
wget https://github.com/suoten/EdgeAgent-Hub/releases/download/v1.0.0/edgeagent-hub-1.0.0-linux-arm64.zip
```

> **国内用户**：如果 GitHub 下载慢，请用 Gitee：
> `wget https://gitee.com/suoten/edgeagent-hub/releases/download/v1.0.0/edgeagent-hub-1.0.0-linux-amd64.zip`

**第 2 步：解压**

```bash
unzip edgeagent-hub-1.0.0-linux-amd64.zip
cd edgeagent-hub-1.0.0-linux-amd64-pkg
```

**第 3 步：一键安装**

```bash
sudo bash install.sh
```

安装脚本会自动完成以下操作：
- 创建 `edgeagent` 系统用户
- 创建目录结构（`/opt/edgeagent-hub`、`/etc/edgeagent-hub`、`/var/lib/edgeagent-hub`）
- 复制二进制文件和配置文件
- 安装 systemd 服务（开机自启）
- 下载并安装 NATS Server（如果没有）
- 初始化数据库
- 启动服务

**第 4 步：验证**

```bash
# 检查服务状态
sudo systemctl status edgeagent-hub

# 检查端口
ss -tlnp | grep 8080
```

看到 `active (running)` 说明服务已正常启动。

**第 5 步：开放防火墙端口（如果需要远程访问）**

```bash
# Ubuntu/Debian
sudo ufw allow 8080/tcp

# CentOS/RHEL
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

然后用浏览器访问 `http://<服务器IP>:8080`。

### 1.3 Docker 安装

> **适合人群**：已有 Docker 环境、需要快速部署多实例

```bash
# 1. 克隆仓库
git clone https://gitee.com/suoten/edgeagent-hub.git
cd edgeagent-hub

# 2. 启动全部服务（EdgeAgent Hub + NATS + ONNX 推理）
docker compose up -d

# 3. 查看运行状态
docker compose ps

# 4. 查看日志
docker compose logs -f edgeagent-hub
```

**仅启动核心服务（不含 LLM，节省内存）：**

```bash
docker compose up -d nats edgeagent-hub inference-onnx
```

**含监控套件启动（Prometheus + Grafana）：**

```bash
docker compose --profile monitoring up -d
```

启动后各服务访问地址：

| 服务 | 地址 |
|------|------|
| EdgeAgent Hub | `http://localhost:8080` |
| Grafana | `http://localhost:3000`（初始账号 admin/admin） |
| Prometheus | `http://localhost:9090` |

### 1.4 验证安装是否成功

无论哪种安装方式，安装成功后你都应该能：

1. **在浏览器中打开** `http://<IP>:8080`，看到登录页面
2. **用 admin / admin123 登录**，看到 Dashboard 仪表盘
3. **Dashboard 上的各项指标**显示正常（即使没有设备数据，页面也不应报错）

如果以上三点都通过，恭喜你，安装成功！

## 第二章 首次登录与安全设置

1. 打开浏览器，地址栏输入：`http://<服务器IP>:8080`
2. 在登录页面输入：
   - 用户名：`admin`
   - 密码：`admin123`
3. 点击「登录」按钮

> **Windows 用户**：双击 exe 后浏览器会自动打开，无需手动输入地址。

### 2.2 修改默认密码（必做）

> **这是最重要的一步！** 默认密码不修改等于裸奔。

1. 登录后，点击右上角的用户名 `admin`
2. 在下拉菜单中选择「个人信息」
3. 在弹出的页面中：
   - 输入当前密码：`admin123`
   - 输入新密码：（至少 8 位，建议包含字母+数字）
   - 确认新密码：再次输入
4. 点击「保存」

### 2.3 创建新用户

如果你的团队有多个运维人员，可以为每个人创建独立账号：

1. 点击左侧菜单「安全管理」
2. 切换到「用户管理」标签
3. 点击「新建用户」
4. 填写信息：

| 角色 | 权限说明 |
|------|---------|

| **操作员** | 可以操作设备、触发工作流、确认告警，不能管理用户 |
| **观察者** | 只读权限，只能查看，不能操作 |

5. 点击「确定」创建用户

## 第三章 设备接入

设备接入是使用 EdgeAgent Hub 的第一步。你的传感器数据需要通过某种协议传给 EdgeAgent Hub，才能触发后续的 AI 推理和告警。

### 3.1 MQTT 方式接入（推荐）

> **适用场景**：绝大多数物联网关、工业网关都支持 MQTT
> **难度**：中等

#### 原理

```
传感器 -> 物联网关 -> MQTT -> EdgeAgent Hub -> AI 推理 -> 告警
```

#### 配置步骤

**第 1 步：确认 EdgeAgent Hub 的 MQTT 地址**

EdgeAgent Hub 自带 MQTT Broker，默认监听 `1883` 端口。你的网关只需要把数据发到 EdgeAgent Hub 所在机器的 `1883` 端口即可。

如果你使用外部 MQTT Broker（比如 EMQX、Mosquitto），修改 `config.yaml`：

```yaml
mqtt:
  broker: "tcp://192.168.1.100:1883"   # 改成你的 MQTT Broker 地址
  client_id: edgeagent-hub
  username: ""                           # 如果 Broker 有认证，填用户名
  password: ""                           # 填密码
  subscribe_topics:
    - sensors/+/+                        # 默认订阅的 Topic
    - devices/+/telemetry
    - alerts/+/+
```

**第 2 步：在网关上配置 MQTT 发布**

在你的物联网关的「MQTT 配置」页面：

| 配置项 | 值 |
|--------|-----|
| Broker 地址 | EdgeAgent Hub 所在机器的 IP |
| Broker 端口 | 1883 |
| 用户名 | （如果没配认证就不用填） |
| 密码 | （如果没配认证就不用填） |
| 发布 Topic | `sensors/vibration/device001` |

**第 3 步：了解数据格式**

网关发送的数据需要是 JSON 格式，例如：

```json
{
  "value": 5.2,
  "unit": "mm/s",
  "timestamp": 1696000000
}
```

或者更完整的格式：

```json
{
  "device_id": "device001",
  "metrics": {
    "vibration_rms": 5.2,
    "temperature": 45.3,
    "power": 78.5
  },
  "timestamp": 1696000000
}
```

**第 4 步：验证数据是否到达**

1. 登录 EdgeAgent Hub Web 界面
2. 点击左侧菜单「设备管理」
3. 如果配置正确，你应该能看到设备出现在列表中
4. 点击「实时监控」，可以看到数据曲线

#### 常见网关 MQTT 配置示例

**有人物联网关（IRQ-1500/IRQ-2000 系列）：**

1. 登录网关 Web 管理页面
2. 进入「云平台」-「MQTT」
3. 服务器地址：`192.168.1.100`（EdgeAgent Hub 的 IP）
4. 端口：`1883`
5. 发布主题：`sensors/vibration/device001`
6. 数据格式选择 JSON
7. 保存并重启网关

**研华 ADAM-3600 系列：**

1. 进入 ADAM.NET Utility
2. 配置 MQTT Connection
3. Broker URL：`tcp://192.168.1.100:1883`
4. Topic：`sensors/+/+`
5. 数据映射到对应寄存器

### 3.2 Modbus 方式接入

> **适用场景**：PLC、变频器、仪表等支持 Modbus TCP 的设备
> **难度**：中等

#### 原理

EdgeAgent Hub 直接作为 Modbus 主站，主动读取从站（PLC/仪表）的寄存器数据。

```
EdgeAgent Hub -> Modbus TCP 请求 -> PLC/仪表 -> 返回寄存器数据 -> 触发推理
```

#### 配置步骤

**第 1 步：获取设备的 Modbus 信息**

你需要知道：
- 设备的 IP 地址
- Modbus 端口（默认 502）
- 从站地址（Unit ID，通常 1-247）
- 寄存器地址和类型（查阅设备手册）

**第 2 步：编辑配置文件**

打开 `config.yaml`，找到 `protocols.modbus` 部分：

```yaml
protocols:
  modbus:
    enabled: true                          # 改成 true
    devices:
      - device_id: "line1.plc1"            # 给设备起个名字（英文+数字）
        host: "192.168.1.100"              # 设备的 IP 地址
        port: 502                          # Modbus 端口
        unit_id: 1                         # 从站地址
        timeout: 3s                        # 读取超时
        poll_interval: 1s                  # 多久读一次（1 秒 = 每秒读一次）
        registers:
          - name: vibration_rms            # 给这个寄存器起个名字
            address: 0                     # 寄存器地址（查设备手册）
            quantity: 1                    # 读取数量
            func_code: 3                   # 功能码：3=读保持寄存器，4=读输入寄存器
            data_type: "uint16"            # 数据类型
            scale: 0.1                     # 缩放系数（原始值 x 0.1 = 实际值）
            offset: 0                      # 偏移量
            unit: "mm/s"                   # 单位（仅显示用）
          - name: temperature
            address: 1
            quantity: 1
            func_code: 3
            data_type: "int16"             # int16 支持负数
            scale: 0.1
            offset: 0
            unit: "C"
```

**数据类型说明：**

| 数据类型 | 说明 | 范围 |
|---------|------|------|
| `uint16` | 无符号 16 位整数 | 0 ~ 65535 |
| `int16` | 有符号 16 位整数 | -32768 ~ 32767 |
| `uint32` | 无符号 32 位整数 | 0 ~ 4294967295 |
| `int32` | 有符号 32 位整数 | -2147483648 ~ 2147483647 |
| `float32` | 32 位浮点数 | 小数 |
| `float64` | 64 位双精度浮点 | 小数（精度更高） |

**缩放和偏移的计算公式：**

```
实际值 = 原始值 x scale + offset
```

例如：温度传感器返回 `453`，实际温度是 `45.3 C`，则 `scale = 0.1, offset = 0`。

**第 3 步：重启服务使配置生效**

```bash
# Linux
sudo systemctl restart edgeagent-hub

# Windows
# 关闭控制台窗口，重新双击 edgeagent-hub.exe
```

**第 4 步：验证**

1. 登录 Web 界面
2. 进入「设备管理」
3. 你应该能看到 `line1.plc1` 出现在列表中
4. 点击该设备，查看「最新数据」，应该能看到 `vibration_rms` 和 `temperature` 的实时值

### 3.3 OPC UA 方式接入

> **适用场景**：西门子、施耐德、ABB 等 PLC，或已有 OPC UA 服务器的场景
> **难度**：较高

#### 配置步骤

编辑 `config.yaml`，找到 `protocols.opcua`：

```yaml
protocols:
  opcua:
    enabled: true
    devices:
      - device_id: "plc_siemens_01"
        endpoint: "opc.tcp://192.168.1.50:4840"   # PLC 的 OPC UA 端点
        security_mode: "none"                      # none / sign / signAndEncrypt
        policy: ""                                 # 安全策略（none 模式下留空）
        cert_file: ""                              # 客户端证书（如果需要）
        key_file: ""                               # 客户端私钥
        auth_mode: "anonymous"                     # anonymous / username
        username: ""                               # auth_mode 为 username 时填写
        password: ""
        timeout: 5s
        poll_interval: 2s
        nodes:
          - node_id: "ns=2;s=Temperature"          # OPC UA 节点 ID
            name: "temperature"                    # 给它起个名字
            unit: "C"
            scale: 0                               # 0 表示不缩放
            offset: 0
            deadband: 0                            # 死区（变化小于此值不更新）
          - node_id: "ns=2;s=Power"
            name: "power"
            unit: "kW"
            scale: 0
            offset: 0
            deadband: 0
```

> **提示**：OPC UA 节点 ID 格式通常是 `ns=<命名空间>;<标识类型>=<标识值>`，例如 `ns=2;s=Temperature` 表示命名空间 2 中的字符串节点 Temperature。具体值请查阅 PLC 文档或用 OPC UA 客户端工具（如 UaExpert）浏览。

### 3.4 HTTP Webhook 方式接入

> **适用场景**：第三方系统通过 HTTP POST 推送数据
> **难度**：中等

#### 配置步骤

**第 1 步：在 `config.yaml` 中启用 Webhook**

```yaml
protocols:
  webhook:
    enabled: true
    listen_addr: ":9091"          # Webhook 监听地址和端口
    path: "/webhook/data"         # 接收路径
    auth_secret: "my-secret-key"  # 认证密钥（客户端需在 Header 中携带）
    allowed_ips: []               # IP 白名单（空=不限制）
```

**第 2 步：重启服务**

**第 3 步：第三方系统推送数据**

```bash
curl -X POST http://192.168.1.100:9091/webhook/data \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: my-secret-key" \
  -d '{"device_id": "sensor_01", "type": "vibration", "value": 5.8, "unit": "mm/s"}'
```

### 3.5 在 Web 界面查看设备

1. 登录 Web 界面
2. 点击左侧菜单「设备管理」
3. 你会看到所有已接入的设备列表：

| 列名 | 说明 |
|------|------|
| 设备 ID | 你在配置中定义的 `device_id` |
| 协议 | 接入方式（MQTT / Modbus / OPC UA / Webhook） |
| 状态 | 在线 / 离线 |
| 最新数据 | 最近一次读取的指标值 |
| 最后通信时间 | 最近一次收到数据的时间 |

## 第五章 工作流配置

### 5.1 什么是工作流

工作流是 EdgeAgent Hub 的核心概念。简单来说，工作流就是一条**自动化处理流水线**：

```
触发条件 -> 第1步（AI推理） -> 第2步（LLM分析） -> 第3步（发通知）
```

你不需要写任何代码，只需要写一个 YAML 配置文件，就能定义完整的 AI 推理 + 告警链路。

### 5.2 内置工作流说明

EdgeAgent Hub 自带 4 个工业工作流，开箱即用：

| 工作流 | 触发条件 | 执行链路 |
|--------|---------|---------|
| **振动异常检测** | 振动 > 4.5 mm/s | ONNX 推理 -> 视觉确认 -> RAG 分析 -> 通知 |
| **温度过热告警** | 温度 > 60 C | ONNX 推理 -> RAG 生成处置建议 -> 通知 |
| **功率超限调度** | 功率 > 100 kW | ONNX 趋势预测 -> RAG 生成调度建议 -> 通知 |
| **电流过载检测** | 电流 > 50 A | ONNX 异常检测 -> RAG 告警 -> 通知 |

这些工作流定义在 `workflows/` 目录中，安装后自动加载。

### 5.3 创建自定义工作流

#### 工作流文件结构

在 `workflows/` 目录（Linux: `/etc/edgeagent-hub/workflows/`）中创建 `.yaml` 文件：

```yaml
# 工作流名称（必须唯一）
name: my_custom_alert

# 触发条件
trigger:
  source: mqtt                                    # 触发来源：mqtt / threshold / manual
  topic: "sensors/pressure/+/+"                  # MQTT 主题（+ 是通配符）
  condition: "value > 10"                        # 触发条件

# 执行步骤
steps:
  # 第一步：ONNX 推理
  - id: detect                      # 步骤 ID（在后续步骤中引用）
    agent: onnx.inference           # 调用哪个智能体
    input:                          # 输入参数
      model_id: "pressure_monitor_v1"
      inputs: "{{ trigger.payload }}"
    output: anomaly_result          # 输出变量名
    timeout: 5s                     # 超时时间
    on_failure: continue            # 失败后：continue（继续）/ abort（终止）

  # 第二步：LLM + RAG 分析
  - id: llm_analysis
    agent: llm.rag_anchored         # RAG 锚定的 LLM 分析
    depends_on: [detect]            # 依赖第一步完成
    input:
      sensor_data: "{{ trigger.payload }}"
      anomaly_result: "{{ anomaly_result }}"
    output: alert_message
    timeout: 30s
    on_failure:                     # 如果 LLM 失败，用模板兜底
      agent: template.fallback_alert

  # 第三步：发送通知
  - id: notify
    agent: notify.multi_channel
    depends_on: [llm_analysis]
    input:
      message: "{{ alert_message }}"
      channels: ["dingtalk", "sms", "webhook"]
```

#### 可用的智能体（Agent）

| Agent ID | 功能 | 输入参数 |
|----------|------|---------|
| `onnx.inference` | ONNX 模型推理 | `model_id`, `inputs` |
| `llm.rag_anchored` | LLM + RAG 分析 | `sensor_data`, `anomaly_result` |
| `llm.chat` | LLM 对话 | `message` |
| `rag.search` | 知识库搜索 | `query` |
| `template.fallback_alert` | 模板告警（LLM 不可用时兜底） | `failed_step`, `error` |
| `notify.multi_channel` | 多通道通知 | `message`, `channels` |
| `vision.camera_check` | 视觉确认（需配置外部摄像头） | `camera_id`, `check_type` |

#### 触发条件说明

```yaml
# 方式1：MQTT 主题触发
trigger:
  source: mqtt
  topic: "sensors/vibration/+/+"
  condition: "value > 4.5"

# 方式2：阈值触发（基于任意来源的数据）
trigger:
  source: threshold
  metric: power
  operator: ">"
  value: 100

# 方式3：手动触发（通过 Web 界面或 CLI）
trigger:
  source: manual
```

#### 条件判断运算符

| 运算符 | 含义 | 示例 |
|--------|------|------|
| `>` | 大于 | `value > 4.5` |
| `<` | 小于 | `value < 20` |
| `>=` | 大于等于 | `value >= 100` |
| `<=` | 小于等于 | `value <= 50` |
| `==` | 等于 | `status == "error"` |
| `!=` | 不等于 | `status != "ok"` |

## 第八章 OTA 模型更新

### 8.1 什么是 A/B 分区

EdgeAgent Hub 使用 A/B 双分区机制来管理模型更新：

```
分区A（当前活跃） <- 正在使用的模型
分区B（备用）     <- 新版本模型写入这里
```

更新流程：
1. 新模型写入分区B
2. 验证通过后，切换到分区B（分区B变活跃）
3. 如果出问题，一键回滚到分区A

这样可以确保**更新失败不会影响正在运行的服务**。

### 8.2 上传新版本模型

1. 进入「OTA 更新」页面
2. 点击「上传新版本」
3. 选择新模型文件
4. 填写版本信息
5. 系统会自动将新模型写入非活跃分区

### 8.3 灰度发布与回滚

#### 灰度发布

1. 在 OTA 页面找到新版本
2. 设置灰度比例（如 10%）
3. 点击「开始灰度发布」
4. 系统会按比例将部分推理请求路由到新模型
5. 观察灰度指标正常后，点击「全量切换」

#### 回滚

1. 在 OTA 页面点击「回滚」
2. 系统会立即切换回上一版本
3. 回滚是秒级的，不会中断服务

#### CLI 操作

```bash
# 查看当前分区状态
edgeagent-hub ota status

# 切换分区
edgeagent-hub ota switch B

# 回滚
edgeagent-hub ota rollback
```

```yaml
  tls:
    enabled: true
    cert_file: "/etc/edgeagent-hub/certs/server.crt"
    key_file: "/etc/edgeagent-hub/certs/server.key"
    ca_file: "/etc/edgeagent-hub/certs/ca.crt"
```

### 10.3 CORS 跨域配置

默认情况下，EdgeAgent Hub 不启用 CORS（同源策略保护）。如果需要从其他域名的前端应用调用 API：

```yaml
server:
  cors_origins:
    - "https://your-frontend.com"
    - "https://admin.your-company.com"
```

> **安全提示**：不要使用 `*` 通配符，这会允许任意网站跨域访问你的 API。

## 第十二章 常见问题与故障排查

### Q1: 启动报错 "Failed to connect to NATS"

**原因**：NATS Server 未运行。

**解决**：

EdgeAgent Hub 自带嵌入式 NATS 服务器，正常情况下不需要额外安装。如果仍然报错，可以手动安装 NATS：

```bash
# Docker 方式
docker run -d --name nats -p 4222:4222 -p 8222:8222 nats:2.10-alpine -js -sd /data

# Linux 手动安装
curl -fsSL https://github.com/nats-io/nats-server/releases/download/v0.25.6/nats-server-v0.25.6-linux-amd64.tar.gz -o /tmp/nats.tar.gz
tar -xzf /tmp/nats.tar.gz -C /tmp
sudo mv /tmp/nats-server-v*/nats-server /usr/local/bin/
nats-server -js -sd /tmp/nats-data &
```

### Q2: 浏览器无法访问 Web 界面

**排查步骤**：

1. 确认服务已启动：`sudo systemctl status edgeagent-hub`（Linux）或检查控制台窗口是否开着（Windows）
2. 确认端口正确：检查 `config.yaml` 中的 `server.port`
3. 确认防火墙：`sudo ufw status`（Ubuntu）或 `sudo firewall-cmd --list-ports`（CentOS）
4. 确认网络可达：`ping <服务器IP>`
5. 确认端口监听：`ss -tlnp | grep 8080`

### Q3: 设备数据收不到

**排查步骤**：

1. 检查设备是否在线：进入「设备管理」页面查看设备状态
2. 检查 MQTT 配置：确认网关的 MQTT Broker 地址指向 EdgeAgent Hub
3. 检查 Topic 格式：确认网关发布的 Topic 与 `subscribe_topics` 匹配
4. 检查数据格式：确认数据是 JSON 格式
5. 查看日志：`journalctl -u edgeagent-hub -f | grep -i mqtt`

### Q4: ONNX 推理返回 "sidecar_offline"

**原因**：ONNX 推理 Sidecar 服务未启动。

**解决**：

```bash
# Docker 方式
docker compose up -d inference-onnx

# 手动方式
cd ai_sidecar
pip install -r requirements.txt
python inference_onnx.py --nats-url nats://127.0.0.1:4222 --model-dir ../models/onnx
```

### Q5: LLM 推理很慢

**解决**：
- 确保使用 Q4 量化模型（如 `qwen3-0.6b-q4_k_m.gguf`）
- 检查内存是否足够（最低 1GB 可用）
- 如果有 GPU，增大 `gpu_layers` 参数
- 考虑使用云端 LLM API（不需要本地资源）

### Q6: 忘记 admin 密码

**方式一：CLI 重置**

```bash
edgeagent-hub -cli reset-password
```

**方式二：手动重置**

1. 停止服务
2. 删除数据库中的 users 表数据：`sqlite3 /var/lib/edgeagent-hub/edgeagent.db "DELETE FROM users;"`
3. 启动服务（会自动重建 admin 用户，密码回到 admin123）

### Q7: Modbus 设备读取不到数据

**排查步骤**：

1. 确认设备 IP 可达：`ping <设备IP>`
2. 确认端口开放：`telnet <设备IP> 502`
3. 确认寄存器地址正确：查阅设备手册
4. 确认功能码正确：读保持寄存器用 3，读输入寄存器用 4
5. 确认 Unit ID 正确：有些设备默认 1，有些默认 255
6. 查看日志中的错误信息

### Q8: 断网后数据会丢失吗？

不会。EdgeAgent Hub 会将数据缓存在本地 SQLite + JetStream 中，网络恢复后自动重传。

### Q9: 支持哪些 AI 模型格式？

- ONNX: `.onnx` 格式，支持 CPU/CUDA/TensorRT/OpenVINO/RKNN
- LLM: `.gguf` 格式 (llama.cpp)，支持 Q4_K_M / Q5_K_M / Q8 等量化

### Q10: 如何查看系统自检结果？

```bash
# Linux
edgeagent-hub selftest -config /etc/edgeagent-hub/config.yaml

# Windows
edgeagent-hub.exe selftest -config config.yaml
```

自检会检查：存储、NATS 连接、MQTT 连接、智能体注册状态等。

### Q11: 如何调整日志级别？

编辑 `config.yaml`：

```yaml
observability:
  log_level: debug    # 改成 debug 可以看到更详细的日志
```

重启服务生效。

### Q12: 端口被占用怎么办？

修改 `config.yaml` 中的 `server.port`，改成其他端口（如 9090），重启服务。
